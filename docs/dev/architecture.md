# Architecture

How the NPU driver and the charsiu port work, as of `main` on 2026-11-24.
The plans and board logs they came from are in [history](../history/README.md).

## Shape

- **Firmware** ([edk2-rk3576](https://github.com/gahingwoo/edk2-rk3576)):
  behind the setup option "NPU (experimental)", off by default, `Npu.c` sets
  the RK806 BUCK2 rail to 800 mV (750 mV at 786 MHz computes wrong), powers
  PD_NPU, then NPUTOP, then NPU0 and NPU1, sets the clock to GPLL/2 = 594 MHz,
  and installs `Npu.asl`: `ACPI\RKCP3576`, registers at `0x27700000`,
  interrupts 279 and 280. The four NPU IOMMUs are left in reset.
- **Driver** (`drivers/rknpu`): a KMDF driver with the job model of mainline
  Linux's `rocket` driver and the RK3576 support in
  [linux-rk3576-npu](https://github.com/gahingwoo/linux-rk3576-npu): buffer
  objects, cache maintenance, job submission, completion interrupts. Its
  interface is `include/rknpu_ioctl.h`.
- **Runtime** (`port/`): charsiu, compiled unchanged from the
  `external/charsiu` submodule with llvm-mingw, except `src/device.c`, which
  `port/device_rknpu.c` replaces, and a few POSIX pieces in `port/compat`.
  `port/libm` is Arm's optimized-routines `expf`, `sinf`, `cosf`, `powf`,
  bit-identical to arm64 glibc on all 2^32 inputs.

An MCDM (compute-only WDDM) driver for DirectML or Windows ML is not
planned: on Windows 11 23H2, the newest release RK3576 can run, MCDM needs a
D3D12 compute driver that compiles shaders, and this NPU is fixed-function.

## Memory: the driver owns the IOMMU

The IOMMU code (`iommu.c`) follows mainline `rockchip-iommu.c` and its v2
page-table format.

- One page directory for all four IOMMU instances (two per core); 4 KiB
  pages, 32-bit IOVA, 40-bit physical addresses; tables write-combined.
- A buffer is pages from anywhere below 2^40, mapped once at CREATE_BO.
  IOVA is handed out in 64 KiB chunks from 1 MiB up, with an unmapped guard
  page after each buffer, so an overrun faults.
- SUBMIT turns paging on when it finds it off (six register reads a job when
  nothing needs doing); paging goes off before a `_DSM` core reset and at D0
  exit, so the next OS finds what the firmware left.
- A page fault stops the job with `RKNPU_JOB_MMU_FAULT`; WAIT resets the
  core and returns the fault address.
- Buffers are limited to 1536 MiB in total.

## Safety

The device interface is administrator-only. Every SUBMIT copies the
command stream into a driver arena (mapped read-only for the NPU) and checks
it: registers on an allow list (`include/rknpu_regcmd_allow.h`, generated by
`tools/m3gen`), no PC-block writes, and every address register inside one of
the caller's buffers. With the IOMMU the NPU can also only reach what the
driver mapped.

## Cache maintenance

CPU mappings are cached. FINI_BO cleans a range (`DC CVAC`) before the NPU
reads it, PREP_BO cleans and invalidates it (`DC CIVAC`) before the CPU reads
NPU output; both are in `cache.asm`. Since M7, FINI is deferred into the next
SUBMIT and PREP is done by WAIT, so a decode call costs 4 IOCTLs instead of
10. charsiu already brackets each CPU access for rocket, so it needed no
change.

## Both cores

The device is not exclusive: charsiu opens two devices and splits each
matmul over both cores. WAIT sleeps on the core's completion event (ISR,
DPC, event) with no lock held. The cores share one CBUF; two jobs that run
at once must use different CBUF windows, so SUBMIT waits when a job's
window collides with the other core's running job. charsiu's two devices use
windows 0 and 1 and never wait.

## Settings

| Where | Name | Default | What it does |
|---|---|---|---|
| `Device Parameters` | `M7WakeBoost` | 1 | the DPC wakes the waiter with a priority boost |
| `Device Parameters` | `M6CachedBos` | 1 | cached CPU mappings; 0 for write-combined |
| `Device Parameters` | `M4AllowUnlisted` | 0 | 1 lets registers off the allow list through (back-out only) |
| environment | `CHARSIU_RKNPU_FUSE` | 1 | 0: one IOCTL per PREP and FINI, as M6 |
| environment | `CHARSIU_WIN_SYSFS` | 1 | 0: do not pin the decode thread to the fast cluster |
| environment | `CHARSIU_RKNPU_ASYNC` | 0 | 1: a call's two SUBMITs overlap |
| environment | `CHARSIU_RKNPU_UCACHE` | 0 | 1: cache maintenance in the process, if user mode may |
| environment | `CHARSIU_NPU_ONEDEV` | 0 | 1: one core only |
